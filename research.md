### Общие закономерности

1. **Два полюса стиля.** Артовые awwwards-портфолио (Holloway, Simon, Parpeix, Benoist) — «портфолио как демо навыков» через 3D/WebGL/GSAP. Конверсионные лендинги (Kristi Digital) — классическая воронка offer → proof → услуги → кейсы → FAQ → контакт. Для продающего портфолио разумно взять структуру второго типа со стилистическими акцентами первого.
2. **Тёмная тема + один яркий акцент** — доминирующий паттерн для технических персональных сайтов (зелёный у Chiang, синий у Holloway, неон у Bondar). Светлые палитры чаще у «продающих» лендингов услуг.
3. **Типографика:** либо grotesque/geometric sans как основа (Monument Grotesque, Founders Grotesk), либо связка serif-editorial + geometric sans для контраста. Monospace-шрифт — регулярный акцент для лейблов/навигации, «технический» сигнал.
4. **Микроинтеракции важнее полноэкранных анимаций** — курсорное свечение, hover-эффекты, плавные переходы создают ощущение «сделано вручную», а не шаблонно.
5. **Личный элемент как обязательный компонент доверия** — фото автора, история от первого лица, реальные имена/лого клиентов в отзывах.
6. **FAQ и «услуги как карточки-офферы»** — почти не встречаются в арт-портфолио, но обязательны в конверсионных примерах: снимают возражения и структурируют оффер.

## 2. Структура лучших лендингов

### Общий список блоков продающего лендинга

По методичке Tilda Education и практическим статьям, лендинг строится из **5 функциональных зон**:

| Зона | Задача | Типовые блоки |
|---|---|---|
| **1. Первый экран** | Произвести впечатление, объяснить «куда я попал» | Обложка: заголовок/оффер + подзаголовок + CTA + меню |
| **2. Рассказ о проекте** | Объяснить предложение полностью | О проекте, для кого (ЦА), этапы работы, тарифы, сравнение с аналогами |
| **3. Понятные выгоды** | Показать отличие и пользу | Преимущества, сценарии использования, результаты «до/после», факты в цифрах, видео |
| **4. Блоки доверия** | Снять возражения | Отзывы, кейсы, портфолио, партнёры/клиенты, команда, гарантии, FAQ |
| **5. Целевое действие** | Довести до конверсии | CTA, форма заявки, контакты, дедлайн, виджеты связи |

Роль ключевых блоков для конверсии:
- **Оффер/заголовок** — удерживает первые 3-5 секунд; без ответа «что мне это даёт» страница не читается дальше.
- **Соц. доказательство** (отзывы, кейсы, логотипы, цифры) — снижает неопределённость и риск решения.
- **Портфолио/кейсы «до-после»** — прямое доказательство результата, критично для digital-услуг без физического продукта.
- **Процесс работы** — снимает страх «а как это будет происходить и не сорвутся ли сроки».
- **Цены/тарифы** — фильтруют нецелевые заявки, снимают страх «дорого/непонятно».
- **FAQ** — закрывает возражения, которые обычно снимает голосом менеджер на созвоне.
- **CTA/контакты** — рекомендуется минимум 2 точки CTA (после hero и в конце страницы).

### Разбор конкретных примеров

**Nia Creative** ([onepagelove.com/nia-creative](https://onepagelove.com/nia-creative)): Header → Hero → Bento-грид портфолио → Список услуг → Форма контакта → Футер. Логика «вдохновение → образование → действие», акцент на визуал.

**READYMAGIC Studio** ([onepagelove.com/readymagic-studio](https://onepagelove.com/readymagic-studio)): Header → CTA-hero → Biography → Портфолио → Форма → Команда (после портфолио, не до) → повторный CTA → Футер. Особенность — двойной CTA.

**Подборка портфолио разработчиков** ([colorlib.com](https://colorlib.com/wp/developer-portfolios/)): Hero с CTA above the fold обязателен на 100% примеров; фильтруемое портфолио по типу/стеку; ссылки на живые демо (не только скриншоты) сильно повышают доверие; закреплённая панель соцсетей/контактов.

**Формула Tilda** ([tilda.education](https://tilda.education/courses/landing-page/anatomiya-landing-page/)): Обложка → О проекте → Преимущества → Портфолио/кейсы → Отзывы → Тарифы → FAQ → Контакты/CTA — эталонная последовательность для большинства продающих лендингов услуг.

**Тренд 2026** ([landingi.com](https://landingi.com/landing-page/41-best-practices/)): лендинг — предсказуемая архитектура с минимумом когнитивных шагов; доверительные блоки измеряются метриками (form start rate после блока доказательств), то есть это не декор, а измеримо конвертирующие элементы.

### Идеальная структура для лендинга-портфолио цифрового специалиста (7 блоков)

Специфика: продукт нематериален, решение о найме строится на (а) доказанной экспертизе, (б) понятном процессе и цене, (в) минимизации риска «сорвёт дедлайн/бюджет». Поэтому портфолио и процесс важнее общих «преимуществ», а тарифы/этапы стоят близко к CTA.

1. **Hero (первый экран)** — оффер + мгновенное доказательство экспертизы.
   Заголовок по формуле «Делаю [что] для [кого], чтобы [результат]» (например: «Разрабатываю сайты, приложения и AI-агентов, которые приносят клиентов бизнесу»); визуальное доказательство — скриншот/анимация реального проекта, а не абстрактная иллюстрация; CTA-кнопка; опционально счётчик «N проектов / N лет опыта».

2. **Услуги / специализация** — 3-5 карточек (сайты и лендинги, веб/моб. приложения, чат-боты, AI-агенты и автоматизация), каждая с формулировкой «для кого» и «что решает».

3. **Портфолио / кейсы с результатами** — ключевой блок. 4-6 кейсов формата «задача → решение → измеримый результат», ссылки на живые демо/репозитории/боты, желательна фильтрация по типу проекта.

4. **Процесс работы** — 3-5 шагов (заявка и созвон → бриф и оценка → разработка с демо → запуск и поддержка), снимает страх «а как это будет происходить».

5. **Социальное доказательство** — 2-4 отзыва с именем и компанией (без анонимных цитат) + блок цифр (лет опыта, проектов, среднего срока, повторных обращений).

6. **Тарифы / варианты сотрудничества** — 2-3 пакета с диапазоном цен «от» и списком, что входит; если фиксированные цены дать нельзя — блок «как формируется стоимость» + CTA на бесплатную оценку.

7. **FAQ + финальный CTA / контакты** — 4-6 вопросов, специфичных для найма фрилансера/AI-специалиста («Как быстро отвечаете?», «Работаете по ТЗ заказчика?», «Что с поддержкой после запуска?»), сразу под FAQ — повторный CTA с формой/мессенджером.

**Итоговая последовательность:** Hero → Услуги → Портфолио/кейсы → Процесс работы → Отзывы/цифры → Тарифы → FAQ + CTA.

Портфолио сознательно стоит выше отзывов и тарифов (в отличие от «универсальной» формулы Tilda) — потому что для цифрового специалиста работы являются главным конверсионным аргументом.

## 3. Тренды и фишки 2026 года

### Анимации и интерактивность

- **Scroll-driven animations (нативный CSS)** — анимация привязана к прогрессу скролла через `animation-timeline: scroll()` / `view()`, без JS. Поддержка ~84% браузеров (Chrome 115+, Edge 115+, Firefox 132+, Safari 18+). Заменяет значительную часть того, для чего раньше подключали GSAP.
- **View Transitions API** — плавные переходы между состояниями DOM или между страницами, полная поддержка во всех трёх движках в 2026.
- **Магнитные кнопки и кастомный курсор** — кнопка «тянется» за курсором в радиусе действия; делается на CSS transform/opacity ради производительности, JS (Motion.dev/GSAP) — только где CSS не хватает.
- **Bento Grid** — модульная сетка карточек разного размера (стиль Apple), стандарт для плотной подачи разнородного контента.
- **Interactive 3D/WebGL** — доступно через no-code инструменты (Unicorn Studio и аналоги) без написания шейдеров вручную.

### Цветовые схемы

- **Dark-mode-first** — тёмная тема как основной дизайн, особенно для SaaS/dev-tools/AI-продуктов.
- **Aurora UI / gradient mesh** — анимированные размытые градиентные «блобы» на тёмном фоне, развитие glassmorphism с акцентом на движение.
- **Glassmorphism 2.0** — блюр используется для иерархии (что кликабельно), точечно — навигация, модалки, а не весь экран.
- **Soft-glow вместо ярких радуг** — «кинематографичные» мягкие градиенты вместо резких неоновых бликов начала 2020-х.
- **Noise/grain-текстуры** — зернистый шум поверх градиентов, чтобы фон не выглядел «стерильно-ИИ-сгенерированным».

### Типографика

- Крупные viewport-масштабируемые заголовки (`clamp()`, `cqw`) как главный визуальный элемент.
- **Вариативные шрифты** — один файл со всеми начертаниями, экономия HTTP-запросов.
- **Кинетическая типография** — текст реагирует на скролл/курсор, анимируются только `transform`/`opacity` (GPU-friendly).
- **Container queries** — типографика подстраивается под размер родительского контейнера, актуально для bento-карточек.

### Специфика AI/tech-продуктов

- **Gradient orbs / ambient glow** — размытые светящиеся «шары» (фиолетовый-индиго-бирюзовый) на тёмном фоне — визуальный синоним «AI-продукта» в 2026.
- **Particle/shader-эффекты** — частицы, liquid-искажения как метафора «интеллекта»/«генерации».
- **Bento grid для фич/стека** — типичный паттерн AI-стартапов, подходит и для показа проектов/навыков.
- **Terminal/code-эстетика** — моноширинные шрифты, блоки кода, мигающий курсор — сигнализирует «это делает разработчик».
- **Прозрачность вместо «магии»** — в UI AI-агентов 2026 акцент на видимом процессе (шаги агента, статусы) — можно обыграть в демо-блоке.
- **Soft-tech пастели vs. неон** — часть AI-брендов уходит от неонового киберпанка к мягким градиентам (лавандовый/мятный) для premium-ощущения; стоит выбрать один полюс осознанно.

### Финальный список: 5 трендов для реализации

**1. Scroll-driven анимации на чистом CSS**
Reveal секций при скролле, прогресс-бар в hero, параллакс gradient-orb фона. Реализация: `animation-timeline: scroll()`/`view()` + fallback для старых браузеров; для сложных сценариев — GSAP ScrollTrigger опционально.

**2. Bento grid для блока услуг/стека**
Модульная сетка карточек разного размера для услуг (сайты/приложения/боты/AI-агенты) и технологий. Реализация: CSS Grid (`grid-template-areas`) + container queries, без JS.

**3. Ambient gradient glow (Aurora UI) в hero**
Размытые анимированные градиентные пятна на тёмном фоне — визуальный сигнал «AI-продукт» без 3D-движка. Реализация: `div` с `filter: blur()` + `radial-gradient` + `@keyframes` на `transform`. Применить в hero и в финальном CTA-блоке.

**4. Магнитные кнопки и кастомный курсор для CTA**
Кнопка тянется к курсору, поднимает ощущение «полировки». Реализация: vanilla JS (`mousemove` + `transform`) или Motion/GSAP `quickTo`; отключить на touch-устройствах через `@media (hover: hover)`. Применить на основных CTA и навигации.

**5. Кинетическая типография в hero + View Transitions между секциями**
Заголовок с посимвольным reveal при загрузке, плавные переходы между фильтрами портфолио или страницами кейсов. Реализация: `clamp()`/вариативный шрифт + `@starting-style`/`animation-timeline: view()` для reveal; нативный View Transitions API для переходов без тяжёлых роутер-библиотек.

## 4. Экспертная оценка

Утверждённая концепция (7-блочная структура + тёмный дизайн с AI-эстетикой) прошла аудит с трёх точек зрения: UX-дизайнер, маркетолог-специалист по конверсии и потенциальный клиент — владелец бизнеса. Каждая роль проверяла факты через веб-поиск, источники указаны инлайн.

### Эксперт 1: UX-дизайнер (10 лет опыта)

#### Типичные ошибки новичков в структуре портфолио-лендингов

1. **Слишком длинный блок «обо мне» перед доказательствами.** У посетителя есть секунды: **86% посетителей уходят с сайта-портфолио менее чем за 30 секунд**, если не находят нужное сразу ([Designlab](https://designlab.com/blog/ux-portfolio-mistakes-to-avoid), [uxplaybook.org](https://uxplaybook.org/articles/11-common-ux-portfolio-mistakes-and-solutions)). Hero проекта уже правильно совмещает оффер + доказательство + CTA — это соответствует «тесту лифта».
2. **Перегрузка проектами без фокуса** — лучше **2-3 сильных кейса**, чем 6+ средних, каждый с историей «проблема → процесс → результат» ([Designlab](https://designlab.com/blog/ux-portfolio-mistakes-to-avoid)). В проекте заявлено 4-6 кейсов — на грани перегруза.
3. **Слабые кейсы без цифр** — общие фразы без деталей процесса не конвертируют, нужен явный measurable result.
4. **Отсутствие визуальной иерархии, «шумная» навигация** ([uxchrisnguyen](https://uxchrisnguyen.medium.com/11-ux-portfolio-red-flags-that-are-killing-your-career-371635410996)). Риск для проекта: тёмная тема + gradient orbs + bento grid + scroll-анимации + кинетическая типографика — пять визуальных систем одновременно, без иерархии они начнут конкурировать с кейсами за внимание.
5. **Игнорирование мобильной адаптации анимаций** — scroll-driven эффекты на слабых мобильных устройствах либо не работают, либо лагают.
6. **Неявный CTA** — оформление явной кнопкой (не ссылкой) даёт **+45% кликов** ([Basis](https://basis.com/blog/15-best-practices-for-higher-cta-conversions)). Стоит добавить повторяющийся CTA после блока соц. доказательства, а не только в начале и в конце.
7. **Копирование трендов без цели** — bento grid/glassmorphism «потому что модно», без функционального обоснования ([rajeshrnair.com](https://rajeshrnair.com/blog/design/ui-ux/ui-design-trends-2026-bento-grids-glassmorphism.html)). Перед вёрсткой нужно явно решить, какие блоки реально выигрывают от bento-формата.

#### Чек-лист «must have» (юзабилити/a11y/техника)

1. **Производительность/Core Web Vitals** — задержка загрузки на 1 сек увеличивает отказы на 32%, рост с 1 до 5 сек — на 90%; **63% пользователей уходят со страниц дольше 4 сек** ([Huckabuy](https://huckabuy.com/20-important-page-speed-bounce-rate-and-conversion-rate-statistics/)). Тяжёлые blur/gradient/WebGL-эффекты бьют по LCP и INP — нужен lazy-load анимаций ниже фолда.
2. **`prefers-reduced-motion`** для всех scroll-driven анимаций — обязательное требование WCAG 2.3.3 ([W3C WAI](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)).
3. **Контраст текста на тёмном фоне по WCAG** (мин. 4.5:1) — не чистый белый на чистом чёрном (глэр-эффект), а мягкий белый на тёмно-сером ([onething.design](https://www.onething.design/post/best-practices-for-dark-mode-ui-design)). Отдельно проверить контраст текста поверх градиентных орбов.
4. **Никакого scrolljacking** — большинство пользователей испытывают дезориентацию от переопределения скорости скролла ([NN/G](https://www.nngroup.com/articles/scrolljacking-101/)). Анимации триггерить по скроллу можно, захватывать сам скролл — нельзя.
5. **Touch-таргеты минимум 44-48px**, упрощённые статичные версии анимаций и bento-grid на мобильном.
6. **Sticky-навигация с якорями** на все блоки, видимая с первого экрана.
7. **Graceful degradation** — контент (оффер, кейсы, CTA, контакты) должен быть читаем, даже если тяжёлые анимации не прогрузились.
8. **Клавиатурная навигация и видимый focus-ring**, который не «съедается» тёмной темой.

#### Что раздражает пользователей и провоцирует уход

1. **Медленная загрузка** — конверсия падает на ~4,42% за каждую доп. секунду; сайт с загрузкой в 1 сек имеет конверсию 39%, с 6 сек — 18% ([Lucky Orange](https://www.luckyorange.com/blog/posts/website-speed-impacts-conversions)).
2. **Автоплей видео/звука** — 71-92% считают раздражающим, свыше трети уходят с сайта ([dejanmarketing.com](https://dejanmarketing.com/auto-play-videos/)). Демо-видео — только по клику.
3. **Scrolljacking** — дезориентация, воспринимается как баг.
4. **Parallax и motion sickness** — расхождение скорости слоёв провоцирует головокружение, ~35% взрослых старше 40 подвержены вестибулярным нарушениям ([Web Axe](https://www.webaxe.org/vestibular-issues-parallax-design/)). Прямой риск для gradient orbs на параллаксе — ограничить амплитуду.
5. **Попапы сразу при входе** — прерывание до того, как посетитель увидел ценность страницы ([Own.page](https://own.page/blog/landing-page-best-practices)).
6. **Скрытые/неочевидные CTA** — должны визуально выбиваться из свечения орбов, а не сливаться с декором.
7. **Любая анимация, отбирающая контроль у пользователя** — топ UI-раздражителей по Nielsen: автовоспроизведение, навязанный скролл, неотключаемая анимация ([Jakob Nielsen](https://jakobnielsenphd.substack.com/p/ui-annoyances)).

**Вердикт UX-дизайнера:** структура из 7 блоков выстроена методически грамотно и соответствует проверенным паттернам конверсионных лендингов. Главный риск — не структура, а стилистическая перегрузка: пять сложных визуальных систем одновременно (тёмная тема, orbs, bento grid, scroll-анимации, кинетическая типографика) должны быть подчинены иерархии, иначе конкурируют друг с другом и с кейсами за внимание — плюс конкретные измеримые риски (производительность, motion sickness, контраст, scrolljacking). Перед вёрсткой нужно зафиксировать бюджет анимаций и «тихий» fallback (`prefers-reduced-motion`, без захвата скролла), ограничить кейсы до 4 сильных вместо шести средних.

### Эксперт 2: Маркетолог (специалист по конверсии)

Оценка утверждённой структуры из 7 блоков с точки зрения конверсии в заявку.

#### Какой оффер зацепит клиента

**Чем оффер одиночного специалиста должен отличаться от агентства и бирж (Upwork/Fiverr).**

У агентства — оффер про масштаб и процессы («команда из 12 специалистов», «полный цикл»). У биржи фрилансеров — оффер, по сути, отсутствует: клиент сам сравнивает десятки похожих профилей по цене и рейтингу, что превращает найм в аукцион «кто дешевле». Единственный способ для одиночки не проиграть в этом сравнении — **не конкурировать в тех же координатах**, а сместить ось сравнения:

- Агентство продаёт «масштаб» → специалист продаёт **скорость решений и прямой доступ к тому, кто реально делает работу** (нет прослойки менеджеров, нет испорченного телефона бриф → менеджер → разработчик).
- Биржа продаёт «дешевизну и выбор из сотни исполнителей» → специалист продаёт **специализацию и предсказуемость**: узкий набор технологий (сайты + приложения + боты + AI-агенты — то есть весь «цифровой стек» одного бизнеса от одного человека) и конкретные измеримые результаты, а не почасовую ставку.
- И агентство, и биржа продают «услугу» → специалист может продавать **результат для бизнеса** («приносит заявки», «экономит N часов»), потому что заказчик нанимает не «разработку», а решение своей бизнес-задачи.

Ключевой психологический принцип для B2B/услуг подтверждается данными: клиенты доверяют больше не общим прилагательным, а измеримым, точным цифрам — точное число воспринимается как результат реального расчёта, а не оценки «на глаз» ([Copyblogger](https://copyblogger.com/specificity-in-copywriting/), [Medium: Paradox of Specificity](https://medium.com/@atticusli/the-paradox-of-specificity-why-precise-numbers-are-more-persuasive-than-round-ones-23cbed7e0cfe)). Также подтверждено, что связка «конкретный результат + конкретный срок» цепляет сильнее абстрактных обещаний, а precise/нечётные числа выигрывают у округлённых по CTR ([Crazy Egg: 101 Headline Formulas](https://www.crazyegg.com/blog/headline-formulas/), [Smart Blogger: Number Psychology](https://smartblogger.com/how-to-write-a-headline-that-converts/)).

**4 варианта оффера/заголовка hero:**

1. **«Сайт, приложение или AI-агент — от одного разработчика, без слоя менеджеров и наценки агентства»**
   *Принцип:* эффект контраста (contrast effect) — оффер явно противопоставляет себя категории конкурентов (агентство), делая цену/скорость специалиста выгоднее на фоне более дорогой альтернативы. Работает, когда посетитель уже сравнивает варианты.

2. **«Уже сделал 30+ сайтов, приложений и ботов, которые приносят клиентам заявки, а не просто "красиво выглядят"»**
   *Принцип:* эффект специфичности (specificity effect) — точное число (не «десятки», а «30+») и конкретный результат («приносят заявки») повышают воспринимаемую достоверность заявления сильнее округлённых формулировок ([источник](https://medium.com/@atticusli/the-paradox-of-specificity-why-precise-numbers-are-more-persuasive-than-round-ones-23cbed7e0cfe)).

3. **«Один разработчик — весь цифровой стек бизнеса: сайт, приложение, чат-бот и AI-агент говорят на одном языке»**
   *Принцип:* узкая ниша vs широкий охват, но здесь ниша определена не по отрасли клиента, а по **типу решаемой проблемы** («разрозненные подрядчики не синхронизированы между собой») — это прямой ответ на боль владельца бизнеса, который иначе нанимает 3-4 разных фрилансера/агентства под каждую систему.

4. **«Отвечаю в течение часа. Первый созвон — в течение суток. Разработку веду сам, от брифа до поддержки»**
   *Принцип:* снижение воспринимаемого риска через прозрачность процесса (process transparency) — конкретное обязательство по срокам ответа работает как микро-гарантия ещё до знакомства с портфолио, что особенно важно для одиночки, где у клиента нет отдела продаж/менеджера, гарантирующего отклик.

Рекомендация: не выбирать один вариант — использовать (2) или (3) как главный H1 в hero (эмоциональный крючок + специфика), а (1) или (4) — как поддерживающий подзаголовок/бейдж рядом с CTA.

#### Какие триггеры доверия нужны

Данные подтверждают: для B2B-услуг ключевые триггеры доверия — это клиентские логотипы/отзывы, гарантии, видимые контакты и live-support с обозначенным временем ответа ([Oktopost](https://www.oktopost.com/blog/trust-signals/), [ProVisors](https://www.provisorsthoughtleadership.com/2025/05/7-trust-signals-to-boost-b2b-conversions/), [SG Digital](https://sgdigitalbusinessdevelopment.com/b2b-website-trust-signals-2026/)). Но у найма **одиночного** специалиста есть специфический риск, которого нет у агентства: так называемый **bus factor = 1** — если разработчик единственный, «пропадёт» или не потянет сложность, проект остаётся без поддержки ([Ekky.dev: Solo Developer vs MVP Agency](https://ekky.dev/blog/solo-developer-vs-mvp-agency-260625/)). Для AI-агентов этот страх усиливается конкретным опасением «хватит ли экспертизы одному человеку на сложную AI-задачу».

Приоритизированный список триггеров с привязкой к конкретному страху и элементу лендинга:

| # | Страх клиента | Триггер доверия | Где на лендинге |
|---|---|---|---|
| 1 | «Пропадёт после оплаты / некому будет поддерживать» | Явное описание послепродажной поддержки: срок гарантии на баги, формат SLA/абонемента на доработки, что происходит с кодом/доступами (передаются заказчику, не «чёрный ящик») | Блок «Процесс работы» — отдельный явный шаг «Поддержка после запуска», + пункт в FAQ |
| 2 | «Не отвечает вовремя, не отдел продаж — вдруг тишина» | Конкретное обязательство по времени ответа («отвечаю в течение 1 часа в рабочее время») + видимый мессенджер-виджет (Telegram/WhatsApp) вместо только формы | Hero (бейдж) + плавающий виджет на всех блоках |
| 3 | «Недостаточно опыта для сложных AI-задач» | Технические доказательства именно по AI-агентам: ссылка на живого бота, архитектура «что под капотом» (не просто «делаю AI-агентов», а конкретные кейсы с интеграциями/моделями) | Кейсы/портфолио — отдельная категория AI-агентов с демо-ссылкой |
| 4 | «Это анонимный фрилансер, не проверить» | Отзывы с проверяемыми ссылками (не скриншот текста, а ссылка на профиль LinkedIn/соцсеть клиента или на реальную компанию), фото и имя самого специалиста, а не абстрактный логотип | Блок соц. доказательства + мини-фото/имя в Hero или Footer |
| 5 | «Непонятно, сколько это будет стоить и не "накрутят" ли смету» | Прозрачные пакеты «от» с составом, а не «цена по запросу»; там, где фикс невозможен — блок «как считается стоимость» | Блок «Тарифы» |
| 6 | «Сорвёт сроки — один человек не может делать всё одновременно» | Явные цифры: средний срок проекта по типам («сайт — 2 недели, AI-агент — 3-4 недели»), количество одновременных проектов в работе (ограничение = сигнал приоритетности, а не перегрузки) | Процесс работы + карточки кейсов («срок: N недель») |
| 7 | «А вдруг просто плохо сделает и пропадут деньги» | Прозрачность процесса оплаты (поэтапная оплата/предоплата % с привязкой к вехам) как имплицитная гарантия | FAQ + блок тарифов |

Важно: гарантия «результат или деньги обратно» из общих B2B-подборок ([ProVisors](https://www.provisorsthoughtleadership.com/2025/05/7-trust-signals-to-boost-b2b-conversions/)) для digital-разработки часто юридически неудобна и обесценивается — лучше заменить её на **гарантию процесса** (бесплатные правки в течение N дней, фиксация ТЗ до старта оплаты) — это работает аналогично, но реалистично для одиночки.

#### Путь посетителя: от «зашёл» до «оставил заявку»

Общий бенчмарк: медианная конверсия выделенного лендинга — около 4-8% в 2026 году в зависимости от методологии, но стадия **awareness (первый экран/первые секунды)** — точка наибольшего отвала, свыше 80% посетителей уходят, не долистав дальше ([Digital Applied](https://www.digitalapplied.com/blog/landing-page-statistics-2026-conversion-data-points), [Amra & Elma: Funnel Drop-Off Stats](https://www.amraandelma.com/funnel-drop-off-rate-statistics/)). Это означает: для этого лендинга Hero и первый скролл — зона наивысшего риска, а не форма заявки в конце.

**Пошаговая воронка для утверждённой структуры из 7 блоков:**

1. **Hero (0-5 сек).** Посетитель проверяет: «попал по адресу?» — понимает ли оффер за 2-3 секунды, видит ли мгновенное доказательство (не текст, а визуал реального проекта). *Точка отвала №1 — самая массовая.* Микро-конверсия здесь неуместна (рано), но CTA должен быть виден без скролла — как первичная, так и вторичная кнопка («Обсудить проект» + мягкая «Смотреть кейсы»).

2. **Услуги (карточки).** Посетитель ищет «свою» категорию (сайт/приложение/бот/AI-агент) — self-selection. Здесь уместна **первая микро-конверсия**: клик на карточку услуги ведёт не сразу на портфолио, а можно вести на быстрый **калькулятор стоимости** («выбери тип проекта → получи вилку цены») — данные показывают, что интерактивные калькуляторы работают как лид-магнит, обменивающий полезный вывод на контакт, и снижают трение по сравнению с формой «оставьте телефон, чтобы узнать цену» ([Outgrow](https://outgrow.co/blog/best-calculator-builders-lead-generation-2026)).

3. **Портфолио/кейсы.** Проверка обещания из Hero конкретными результатами. *Точка отвала №2* — если цифры результатов расплывчаты («улучшили сайт»), доверие проседает. Микро-конверсия: для AI-агентов и ботов — **живое демо** (виджет чат-бота прямо в кейсе, с которым можно списаться) вместо статичного скриншота. Это не просто иллюстрация, а прямое доказательство навыка «в моменте», и по данным чат-бот-лендинги конвертируют кратно выше статичных форм (в некоторых кейсах — конверсия чат-бот-лидов свыше 40% против ~2,35% у обычной формы, см. [Landbot](https://landbot.io/blog/lead-generation-chatbot-tutorial)); к этой цифре стоит относиться как к верхней границе одного кейса, а не universal benchmark, но направление верно.

4. **Процесс работы.** Снимает рациональные возражения («как это будет происходить»). Здесь низкий риск отвала, если шагов не больше 5 и они конкретны.

5. **Соц. доказательство (отзывы + цифры).** Подкрепляет эмоционально. *Микро-конверсия:* если отзывы кликабельны (ссылка на реальный профиль/сайт клиента) — это не столько конверсия, сколько усилитель доверия перед решающим блоком тарифов.

6. **Тарифы.** *Точка отвала №3 — вторая по величине после Hero.* Если цена «по запросу» без ориентиров — часть посетителей уходит, не оставив контакт, потому что боятся «начать диалог, чтобы узнать, что не по карману». Решение: пакеты «от» + сразу рядом мягкий CTA «не уверены, что выбрать — обсудим бесплатно 15 минут».

7. **FAQ + финальный CTA.** Последний шанс закрыть возражения перед формой. Здесь важно продублировать **мессенджер-виджет** (Telegram/WhatsApp) рядом с формой как альтернативный низкопороговый канал — интеграция мессенджеров повышает конверсию лидов за счёт более быстрого и привычного канала связи и на данных показывает рост конверсии порядка 30% при переходе с формы на мессенджер за счёт скорости ответа ([источник по WhatsApp/Telegram виджетам](https://www.chatarchitect.com/news/cross-platform-strategies-integrating-whatsapp-with-telegram-and-beyond)).

**Рекомендуемые микро-конверсии (по убыванию приоритета для этого лендинга):**

1. **Плавающий мессенджер-виджет** (Telegram/WhatsApp) на всех блоках — самый низкопороговый шаг, доступен с любой точки страницы, не только в конце.
2. **Живой чат-бот-виджет как демо** внутри блока портфолио/кейсов AI-агентов — одновременно инструмент продаж и доказательство квалификации: посетитель убеждается в навыке, «пощупав» продукт.
3. **Калькулятор стоимости** («тип проекта + сложность → вилка цены») перед блоком тарифов или встроенный в него — снижает страх «непонятно, сколько это будет стоить» и создаёт мягкую точку входа для тех, кто ещё не готов писать в мессенджер.
4. **Сокращённая форма заявки** (2-4 поля: имя, контакт, тип проекта — без телефона/бюджета на первом шаге) — данные показывают, что уменьшение формы с 9 полей до 4 и добавление интерактивного демо подняло конверсию с 0,9% до 2,7% в одном из измеренных кейсов ([SaaSHero](https://www.saashero.net/strategy/b2b-saas-conversion-rate-benchmarks/)); детали квалификации (бюджет, сроки) переносятся на созвон, а не на форму.

#### Вердикт маркетолога

Структура из 7 блоков конверсионно грамотная и уже расставляет портфолио/кейсы выше тарифов и отзывов — это правильно для нематериальной услуги, где доказательство важнее убеждения. Главный риск — Hero: если оффер там прозвучит как «я делаю сайты» вместо специфичного, с цифрами и противопоставлением агентству/бирже, будет потерян основной объём трафика ещё до первого скролла (по отраслевым данным это самая массовая точка отвала). В первую очередь нужно усилить три вещи: (1) переписать оффер hero по формуле специфичность + контраст с агентством/Upwork, а не общий тезис; (2) добавить в блок портфолио живое демо чат-бота/AI-агента как микро-конверсию и прямое доказательство экспертизы, а не только скриншоты; (3) закрыть специфичный для одиночки страх «bus factor» явным шагом поддержки в процессе работы и/или FAQ — иначе даже сильное портфолио не снимет опасение «а если пропадёт после оплаты».

### Эксперт 3: Клиент — владелец бизнеса (не технический специалист)

Проверка фактов о поведении посетителей перед оценкой: первое суждение о доверии к сайту формируется за **50 миллисекунд** ([ResearchGate](https://www.researchgate.net/publication/220208334_Attention_web_designers_You_have_50_milliseconds_to_make_a_good_first_impression_Behaviour_and_Information_Technology_252_115-126)); развёрнутое первое впечатление складывается за 0,2-2,6 сек, «поверить» сайту — до 3-5 сек ([iservu.com](https://iservu.com/blog/website-first-impression-50-milliseconds/)); B2B-пользователи решают, оставаться ли, за 5-8 секунд, и **88% посетителей после плохого опыта не возвращаются** ([contentgrip.com](https://www.contentgrip.com/website-first-impressions-5-seconds/)); **70% B2B-сайтов теряют лиды из-за плохого UX** ([DesignRush](https://news.designrush.com/70-b2b-sites-lose-leads-bad-ux-next)); 45% B2B-покупателей называют непрозрачные цены главным раздражителем при выборе подрядчика.

#### На что клиент смотрит в первые 5 секунд

1. **Заголовок крупным шрифтом** — читает бегло, ровно один раз. Главный вопрос: «это вообще про меня, или это для айтишников/стартаперов?» Термины вроде «AI-агент», «нейросети», «автоматизация» без человеческого перевода — вызывают напряжение, а не интерес.
2. **Фото или видео человека** — ищет глазами лицо: «он реальный человек или шаблон с Fiverr/Envato?» Тёмный дизайн с анимациями по умолчанию воспринимается как «дорого» — а значит ли это «дорого для меня»?
3. **Кнопка/CTA** — почти рефлекторно ищёт, куда нажать, даже не решив ещё, будет ли действовать. Текст кнопки важен: «Обсудить проект» — понятно, «Начать» — непонятно, что начнётся.
4. **Скролл вниз одним движением** — неосознанная проверка «это серьёзный ресурс или пустышка на один экран».
5. **Цифры боковым зрением** («20 проектов», «3 года», «ответ за 24 часа») — воспринимаются честнее, чем слова.
6. Параллельно в голове: «Он потом не пропадёт, как предыдущий фрилансер?», «Он вообще понимает мой бизнес или только умеет в код?», «Сколько это будет стоить хотя бы примерно?»

#### Останусь / закрою вкладку

**Останусь читать и дойду до заявки, если:**
1. Заголовок за 3 секунды объясняет на человеческом языке, что делает специалист — без жаргона «оркестрация LLM».
2. Есть живое лицо/имя — фото, короткое видео-приветствие, а не безликий «digital creator».
3. В портфолио — кейсы с конкретными цифрами и **рабочими** ссылками на демо (клиент, скорее всего, кликнет хотя бы одну, чтобы проверить, что это не фейк).
4. Отзывы выглядят как настоящие люди: имя, компания, проверяемая ссылка — а не «Иван П., клиент».
5. Виден порядок цены («от 60 000 ₽») — так клиент понимает, в его ли он «лиге», не тратя время зря.
6. Тёмная тема и анимации не мешают читать текст и цены — стильно, но быстро и без «плывущего» контента.

**Закрою вкладку, если:**
1. Первый экран — красивая картинка без понятного текста (только градиенты/орбы, а что за услуга — непонятно, пока не проскроллишь).
2. Сайт тормозит/дёргается при скролле на не топовом устройстве — читается как «непрофессионально», несмотря на весь AI-дизайн.
3. Портфолио — это макеты без ссылок, либо ссылки на демо, которые не открываются.
4. Отзывы без имён и фото, звучат сгенерированно («Отличная работа, всё супер!»).
5. Нигде нет ни цены, ни порядка цены — везде «напишите нам, обсудим», что ощущается как «будут вытягивать деньги в переписке».
6. Текст перегружен терминами («нейросетевая оркестрация», «мультиагентная архитектура») без перевода на пользу для бизнеса — клиент чувствует себя глупым и уходит к тому, кто объяснит проще.

**Моё решение (от лица клиента):** в нынешней концепции — тёмный дизайн с орбами и кинетической типографикой — клиент, скорее всего, задержится на сайте, но заявку оставит не с первого захода, а только если встретит живые кейсы с цифрами, настоящие отзывы с именами и хотя бы примерные цены; без этого — закроет вкладку, приняв сайт за «модный, но пустой» лендинг. Чтобы клиент точно написал: нужен человеческий, не жаргонный оффер в hero («делаю сайты и ботов, которые приносят вам клиентов и продажи, а не просто выглядят красиво»), фото/видео реального человека и цены «от» видно без скролла до шестого блока — и сайт должен быть быстрым, иначе идея «эксперт по современным технологиям» разобьётся о первое же лагающее движение курсора.

### Общий список рекомендаций (пересечение всех трёх экспертиз)

Пункты, которые независимо подтвердили минимум два эксперта из трёх — самые приоритетные для доработки концепции:

1. **Оффер в hero должен быть на человеческом языке, с конкретикой и цифрами, без AI-жаргона.** UX и маркетолог сходятся на специфичности («30+ проектов» вместо «делаю сайты»); клиент прямо говорит, что жаргон («оркестрация LLM», «мультиагентная архитектура») заставляет чувствовать себя глупым и уходить.
2. **Стилистическая перегрузка — главный риск концепции.** UX предупреждает, что 5 визуальных систем сразу (тёмная тема + orbs + bento grid + scroll-анимации + кинетическая типографика) конкурируют за внимание и создают риски производительности; клиент подтверждает с другой стороны — если сайт лагает или первый экран это только «красивая картинка без текста», он закрывает вкладку. **Вывод:** ограничить одновременное количество эффектов, дать понятный текст с первого экрана без прокрутки.
3. **Кейсы — с рабочими ссылками на живые демо, а не скриншотами.** Все три эксперта считают это критичным: UX — как антидот «слабым кейсам без цифр», маркетолог — как лучшую микро-конверсию (особенно демо чат-бота/AI-агента), клиент — как способ проверить, что это не фейк.
4. **Цена «от» должна быть видна без глубокого скролла.** Маркетолог и клиент независимо называют непрозрачную цену главной причиной отвала на блоке «Тарифы»/во всей воронке; UX подтверждает через общий принцип «снижения трения».
5. **Отзывы — только с проверяемыми ссылками на реальных людей/компании.** Маркетолог включает это в топ-триггеры доверия, клиент прямо помечает отзывы без имён и фото как «первое, что читается как фейк».
6. **Явный, «не сливающийся с декором» CTA, продублированный минимум дважды.** UX (+45% кликов от кнопки против ссылки, повтор CTA после соц. доказательства) и маркетолог (мессенджер-виджет на всех блоках, вторичный CTA в каждой точке отвала) солидарны в этом.
7. **Ограничение анимаций: `prefers-reduced-motion`, никакого scrolljacking и автоплея.** Чисто UX-пункт, но напрямую поддержан фактом от клиента: лаги/дёргание при скролле — мгновенная причина ухода, независимо от того, как красиво выглядит AI-эстетика.
8. **Закрыть специфичный страх «специалист один, а не команда» явным шагом поддержки.** Маркетолог называет это «bus factor», клиент формулирует то же самое проще: «он потом не пропадёт, как предыдущий фрилансер?» — нужен явный блок/пункт FAQ про поддержку после запуска.
